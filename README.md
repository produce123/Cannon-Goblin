# Cannon Goblin · 大炮轰小鬼

一个**不依赖任何服务器**的不对称策略棋盘游戏。纯静态页面（零依赖、零构建），
联机对战走 **WebRTC 点对点直连**，双方交换两段代码即可开局。

🎮 在线玩：**https://produce123.github.io/Cannon-Goblin/**

---

## 玩法

| | 大炮方 💣 | 小鬼方 👻 |
|---|---|---|
| 数量 | 2 枚 | 18 枚 |
| 先手 | ✅ | |
| 移动 | 横竖走一格到相邻空格 | 横竖走一格到相邻空格 |
| 吃子 | 隔**恰好一个空格**吃掉同一直线上的小鬼 | 不能吃子，只能围堵 |

**胜负**

- 大炮方获胜：场上小鬼数 **≤** 大炮数
- 小鬼方获胜：所有大炮都被堵死，一步也走不了

## 三种模式

- **本地对局** — 两人同一台电脑轮流走
- **人机对局** — 三档 AI 只差"预判几步"：简单 **1 步** / 普通 **2 步** / 困难 **4 步**
  （同一套 alpha-beta 搜索，困难那档带时间预算，算不完就退回上一层结果，不会把界面卡住）
- **在线对局** — 6 位房间号进房，能直连就直连、打不通自动走中转，见下

另外还有预设地图、自定义棋盘尺寸、以及可自由摆放初始棋子的地图编辑器。

## 在线对局怎么连（手机流量 / 校园网 / 运营商网络都能玩）

**一句话：房主建房得到一个 6 位房间号，发给对手，对手输进去就进房了。**
不需要回传任何东西，也不需要谁有公网 IP 或服务器。

**房主**

1. 菜单 → 在线对局 → 点 **创建房间**
2. 把显示出来的 **6 位房间号**（例如 `K7M2QF`）发给对手
3. 对手进房后，双方都会进入**准备界面**；你在那里选**自己执大炮方还是小鬼方**、
   选预设地图、改棋盘尺寸，或者点 **编辑初始位置** 自己摆棋子
4. 点 **开始游戏**，双方同时进入棋盘。**大炮方先走**，所以你要是选了小鬼方，
   就先由对手走第一步

**加入方**

1. 菜单 → 在线对局 → 把房间号输进输入框 → 点 **加入房间**
2. 进入准备界面等待房主选地图和站位，他点开始后自动进入棋盘（你执房主的对面那一方）

**中途有人退出怎么办**

对手（或你自己）点了「返回」离开房间后，**房间还开着**：让离开的人用**同一个房间号**
再输一次就能重新进房，双方回到准备界面，房主点开始就是一局新的。
（直连断掉时房主这边也会自动放开房间，不会锁死。）

> 只同步"一手棋"，不同步整个棋盘：双方本地跑同一套规则，所以流量极小（每步几十字节）。

### 它是怎么打通的

握手需要一个"双方都能连出去"的公共中转点，因为手机 5G、校园网、运营商网络
大量处于对称 NAT / CGNAT 后面，而**免费的公共 TURN 中继已经不可用**（实测域名失效）。
所以这里用**公共 MQTT broker** 当房间与信令通道（双方都只是往外连，跟 NAT 无关）：

| 阶段 | 走哪条路 |
| --- | --- |
| 房间号 → 找到对手 → 交换握手信息 | 公共 MQTT broker（依次尝试 EMQX → HiveMQ → mqtt-dashboard） |
| 对局数据（每一手棋） | 优先 **WebRTC 直连**（延时最低） |
| 直连打不通时 | 自动改走 **MQTT 中继**，由房主单方面决定并广播，两端行为一致 |

准备界面右上角会写明当前是 **直连模式** 还是 **中转模式**，一看就知道走的是哪条路。
所以：家庭宽带/同一 WiFi 通常是直连；双方都在对称 NAT 后会自动降级成中转，**照样能玩**，
只是每步棋要绕一趟公共 broker（棋类游戏完全无感）。

### 想更自主一点

- **换自建 broker**：URL 后面加 `?brokers=wss://你的域名:8084/mqtt`，可用逗号写多个做后备。
- **排查直连问题**：加 `?transport=relay` 可以强制走中继，用来确认"中转本身没问题"。
- **前提**：需要 Chrome / Edge / Safari 等现代浏览器（要有 WebRTC 与 WebSocket）。

## 本地运行

没有构建步骤，改完刷新即可。

```bash
# 推荐：起个本地静态服务器（localhost 属于安全上下文）
npx serve .
# 或
python -m http.server 8000
```

也可以直接双击 `index.html`。但 `file://` 下部分浏览器会限制 WebRTC 与剪贴板 API，
**联机建议走上面的本地服务器或直接用 GitHub Pages 地址**。

## 测试

```bash
node --test tests/game.test.mjs   # 单元用例
node tests/browser/run.mjs        # 真实浏览器端到端（自动找 Chrome / Edge）
```

**单元用例**覆盖 MQTT 报文编解码（CONNECT / SUBSCRIBE / PUBLISH、长度字段跨字节、
字节流分片重组、半截报文不吐出来）、房间号生成与归一化、房间话题方向与定向投递（sid），
关键不变量：**双方各自本地重放同一串走子后局面必须完全一致** —— 这是在线对局
只同步"一手棋"的前提，以及三档 AI 的合法性 / 搜索深度 / 耗时上限。

**浏览器 E2E** 会起一个临时静态服务器 + **一个内置的极简 MQTT broker**（所以测试不依赖
公网），用无头浏览器开多个 iframe 各跑一份真实 `index.html`，完整走一遍
「建房 → 房间号进房 → **房主改执小鬼方**（加入方自动变大炮方，由加入方先走）→
双方准备界面 → 房主选地图开局 → 双方各走一手 → 两条重开路径 → 第三人抢同一房间号被拒 →
**对手离开后用同一房间号重进** → **强制中继模式再来一遍（含重进）** →
**手机窄屏下棋子与网格交点的对齐** → 本地对局与三档人机各出一手」，
并检查页面内没有任何被吞掉的 async 报错。

想顺便验证真实的公共 broker 链路：`E2E_PUBLIC=1 node tests/browser/run.mjs`。
想顺带验证高分屏：`E2E_DSF=3 node tests/browser/run.mjs`。

## 目录结构

```
index.html                所有界面（菜单 / 设置 / 编辑器 / 联机大厅 / 准备界面 / 棋盘 / 规则）
favicon.png               站点图标（💥，128×128）
css/style.css             所有样式
js/game.js                规则引擎 GameState + 预设地图
js/ai.js                  三档 AI
js/audio.js               WebAudio 合成音效（无音频文件）
js/mqtt.js                极简 MQTT over WebSocket 客户端（零依赖手写）
js/room.js                联机房间层：房间号 / 信令 / WebRTC 优先 + 中继降级
js/app.js                 界面控制与对局收发
tests/game.test.mjs       node:test 单元用例
tests/browser/run.mjs     E2E 运行器（静态服务 + 内置 MQTT broker + 无头浏览器）
tests/browser/online.html E2E 用例页面（多个 iframe 跑真实 index.html）
tests/browser/broker.mjs  E2E 专用的极简 MQTT broker
functions/                可选旧版后端（Supabase Edge Function），前端已不再使用
```
